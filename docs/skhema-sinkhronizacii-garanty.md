## Как отличается правка человека от нашей записи
- `exp[поле]` — что мы последний раз прочли в таблице, `expPending[поле]` — что записали, но ещё не прочли.
- Значение в таблице ≠ обоих → это правка человека: применяется, поле помечается `manual`, Excel его больше не трогает.
- Запись не дошла (в таблице старое `exp`) → это не правка, запись повторяется (тест `write_not_landed`).
- Первое знакомство со строкой (exp пуст) → берётся значение таблицы, без пометки `manual`.

## Новые строки и сортировка
- Строка без ID с клиентом/договором/суммой → ID `G-<следующий>`; ключ содержимого → `pendingIds`, поэтому повторный pull до записи ID даёт тот же ID, а не новый.
- Две одинаковые новые строки → два разных ID (ключ + порядковый номер).
- Всё сопоставляется по ID, не по номеру строки: сортировка и фильтры менеджера ничего не ломают.
- Строку удалили из таблицы → в реестре остаётся с пометкой `sheetGone`, в отчёт «пропала из таблицы».
- Платёж без ID: нужен выбранный клиент (метка `G-… · …`) и сумма, иначе «не выбран клиент», в расчёт не идёт. С ними → `P-M-<n>`, частичная оплата уменьшает остаток.

## Запись в таблицу (`plan`)
- Один диапазон на вкладку, неизменённые ячейки = null (Sheets их пропускает, формулы J–N целы).
- «Банк» перезаписывается целиком (её пишет только Claude).

## Защита (protectedRanges, warningOnly=false, редактор — только владелец)
- «Реестр»: шапка; J–N формулы; O–P (Источник, Проверено); R (Что сделать); T–V служебные.
- «Платежи»: шапка; A (ID); E (Вид); G–I (счёт, п/п, источник).
- «Банк», «Этот месяц», «Следующий месяц», «Месяцы», «Контроль», «Миграция», «Журнал», «Как пользоваться» — целиком.
- «Зарплата» — целиком, кроме записи Лены D7:I19 и L7:L19; ставки B2:B3 и формулы B, C, J, K правит только владелец.
- Менеджер вводит: «Реестр» B–I, Q, S; «Платежи» B, C, D, F, J. Сортировка — через режим фильтра (у каждого свой).
