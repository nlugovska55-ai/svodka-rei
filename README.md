# Сводка дня РЭИ на Vercel

Закрытая страница для Ольги: обычная ссылка в браузере, вход по паролю.
Репозиторий GitHub `nlugovska55-ai/svodka-rei` (private) → Vercel выкладывает каждый push сам.

## Стиль и первый экран (29.10.2026)

Стиль rus-ei.ru по бренд-брифу 28.10 (утверждён 22.10): текст #243329, вторичный #59665D, кнопка #286534 (наведение #1f5229), надзаголовок #397C4D, фон #F2F6EF, рамки #D5E3D0/#cfdcc8, мягкий зелёный #e4efdd. Заголовки Exo 2 700, текст Open Sans 400/600 (запасные Segoe UI, Arial), 15px/1.6. Кнопки 8px, главная высотой 50. Карточки 6–10px без теней. Только светлая тема. Логотип с rus-ei.ru; если не загрузился, вместо него знак «РЭИ». Плюс #286534, минус #c0392b, числа tabular-nums.

Первый экран «Утра»: плашка охвата (сколько дел сверено сегодня, что это не полный список, сколько ещё не сверено), три приоритета карточками (следующий шаг, кто, срок, блокировка, ссылка на источник: заказ портала, Диадок, черновики почты, ЦРПТ), остальные сверенные дела строками, план недели только по due из карточек дел. Этап «Пришло по карточкам дел» отделён от блока «Банк, факт по выпискам» (svodka/bank-oboroty.json, по счетам и дням, с охватом). «Автоматика»: зелёный только у статуса, проверенного сегодня; вчерашний серый, с пометкой «сегодня не проверено».

## Из чего состоит
- `index.html` — пульт «Утро» (вкладки Утро / Деньги / Все дела, разбор по одному делу, отметки с отменой, свайпы, клавиши). Без сборки и библиотек, шрифты Google Fonts.
- `old.html` — прежний вид таблицами (ссылка «Старый вид» внизу пульта).
- Поля задачи для пульта (ветки могут писать в db, иначе сайт вычисляет сам): `short` — заголовок до 60 знаков «глагол + что», `waiting` — я / клиент / Лена / Claude, `urgency` — сегодня / неделя / фон. Отметки с сайта (`done`, `later`, `eve`, `prio`, `wait`, текст для Claude) уходят через `api/comments.js` в ветку inbox.
- Сверка: `checked` — «ДД.ММ …», «ДД.ММ.ГГГГ …» или ISO; «сегодня» только при совпадении даты по МСК (прошлый год и будущее не проходят).
- Деньги: одна операция в «пришло» и на другом этапе вычитается только при одинаковом явном `dedupe` / `invoice` / `payment`; без него одинаковые клиент и сумма показываются как «возможный дубль», обе суммы остаются.
- Отметки: у каждой `eid`, партия уходит с `batchId` (повтор той же партии сервер принимает без второго файла, другое содержимое — 409). GET `/api/comments` отдаёт отметки за 48 ч страницами (`nextCursor`), неполный список — ошибка. Отметка «ждёт синхронизации» снимается только когда её `eid` есть в `appliedEvents` сводки: это `eventId` комментариев db со статусом done. Поэтому выгрузку db для `build_svodka.py` делать с `tasks` и `comments`.
- `data/svodka.json` — данные: `{updated, tasks[], summary[]}`. Меняется только этот файл.
- `middleware.js` — страница входа по паролю, вход помнится 30 дней (cookie); принимает пароль и в другой раскладке. Пароль в Vercel: Settings → Environment Variables → `DASH_PASSWORD`. Без него сайт закрыт полностью.
- `scripts/build_svodka.py` — собирает `data/svodka.json` из выгрузки db `tasks` и файла `summary.json`.

## Кто что делает
- **«Утро и задачи» (Sonnet, low)** — единственный, кто выкладывает сайт. Будни 9:30 МСК: утренний сбор, `summary.json`, выгрузка. 13:00 и 17:00: только выгрузка свежей db (без чтения почты).
- **«Бухгалтерия» (Opus, medium)** — ведёт свои задачи в db (cat `tax`, `supplier`, owner «Лариса»); закрытое отмечает `status: done`. Сайт сама не выкладывает.
- **«Браузер» (Sonnet, low)** — задачи Диадока (cat `edo`) и оплат портала/банка (cat `pay`, поле `money`: ждём | пришло | выставить счёт) в db.
- **«Управление проектами» (Opus, medium)** — раз в день пишет «Утру» 1–2 строки состояния проектов для блока «Проекты».
- Срочное днём (оплата пришла, подписано): ветка правит db и пишет «Утру» `message_thread` «обнови сводку» — та выгружает вне расписания.

Одна выкладывающая ветка — нет конфликтов в git и лишних токенов у других веток.

## Как выгрузить (ветка «Утро и задачи»)
1. `ArtifactData list` url=https://claude.ai/artifact/3FMn9JyWFXrL6ZzgAx5JAY collection=`tasks` query.limit=1000 out_dir=`<tmp>/db`
2. `python3 -I scripts/build_svodka.py <tmp>/db /mnt/project-files/daily-control/svodka/summary.json data/svodka.json`
3. `git add data/svodka.json && git commit -m "Сводка <дата время>" && git push` → через ~30 сек. на сайте.

Правила раздела и денег (`section`, `money`) — в `build_svodka.py`; если в задаче db есть поле `money` или `section`, берётся оно.
Страница сама перечитывает данные каждые 10 минут, при возврате на вкладку (если прошло больше минуты) и в полночь по Москве; дата «сегодня» и свежесть считаются по МСК заново при каждом обновлении. Если открыта карточка, есть черновик, идёт разбор по одному или окно «Отменить», перерисовка откладывается на 30 с. Свежесть: пропущенная выкладка — «Устарело: …» с жёлтой точкой; данные другого дня — плашка «сегодня сводку ещё не выкладывали»; ошибка обновления — пометка в шапке, на экране остаются данные прошлой загрузки.

## Комментарии с сайта (кнопка 💬 и «Отправить Claude»)
- У каждой задачи клиента и у активных клиентов Лены кнопка 💬: комментарий и быстрый статус (на вечер, в приоритет, ждём клиента, сделано). Черновики хранятся в браузере, «Отправить Claude» наверху шлёт все разом.
- `api/comments.js` (Vercel, за тем же паролем) кладёт их файлом `inbox/<время>.json` в ветку `inbox` этого репозитория (ветка не выкладывается, см. `vercel.json`). Нужна переменная Vercel `GITHUB_TOKEN` — fine-grained токен только на `svodka-rei`, Contents: Read and write. Без неё кнопка честно пишет «Не задан GITHUB_TOKEN», черновики не теряются.
- На разборе комментариев (10:00, 13:00, 18:00), импорт двухфазный: `git fetch origin inbox` → выгрузить db `tasks` в `<tmp>/tasks` → `python3 -I scripts/inbox_to_db.py prepare . /mnt/project-files/daily-control/svodka-site/inbox-imported.txt <tmp>/batch.json <tmp>/tasks` (учёт не меняется) → ArtifactData batch из batch.json страницы задач **строго по порядку**: сначала `update` в `tasks`, потом `set` в `comments` → прочитать из db (get по doc_id из манифеста) записанные комментарии и задачи из `taskDocs`, сохранить в `<tmp>/applied.json` как `{"comments": [id], "tasks": {id: документ задачи из db}}` → `python3 -I scripts/inbox_to_db.py ack . <файл-учёта> <tmp>/batch.json <tmp>/applied.json` (ack сверяет каждое поле patch задачи с прочитанным из db, порядок batch доказательством не считается; код 1 — повторить с prepare; ошибка git — код 2, импорт остановлен). Тест: `python3 -I tests/inbox_import.test.py`.
  Кнопки сайта → задача db (только последнее событие по задаче): «Я выполнила» (после подтверждения) → `status: "done"`; «Поручить Claude» → `status: "open"`, `waiting: "Claude"`, `delegated: <eid>` (дело не закрывается, его ведёт Claude); «Вернуть» → `status: "open"`, `waiting: ""`; ждём клиента → `status: "wait"`; на вечер → `evening: true`; горит → `prio: true`; отложить — только на сайте. Сообщение без действия (в т. ч. старые с action пусто) задачу не меняет и ждёт разбора со `status: "new"`.
- Раздел «Бухгалтерия» на сайте: реестр списаний `svodka/spisaniya.json` (ведёт «Бухгалтерия»: kind plan/reference, paid + paidSrc), последняя `kontrol/buh-svodka-*.md`, дела Бухгалтерии из db. Обороты банка — из `svodka/bank-oboroty.json` (ведёт «Бухгалтерия» по прочитанным выпискам: account, date, open, in, out, close, inItems/outItems, src; вход + приход − расход должен равняться концу, иначе сборка остановится). Сайт показывает их только по охваченным счетам и дням, «не полный факт месяца»; нет файла — «Факт по банку не получен». Сроки дел со счётом/подписью — «срок контроля», не дата оплаты.
- На сайте статусы видны в колонке «Статус»; фильтры «На вечер» и «Ждём клиента» на вкладке «Клиенты».

## Telegram-боты Claude и GPT (api/tg.js)
Два бота в одном коде: бот Claude (webhook `/api/tg`) и бот GPT (`/api/tg?bot=gpt`). Ольга пишет любому — бот отвечает и передаёт сообщение Claude на разбор.
- Команды у обоих: `/nuzhno` (блок «Нужно от вас» + дела, где ждут Ольгу), `/dengi` (деньги по этапам), `/gorit` (срочность «сегодня» и ручной приоритет), `/id`. Отвечают по `data/svodka.json` без ИИ.
- Любой другой текст ложится в ветку `inbox` (`source: "telegram"` или `"telegram-gpt"`), разбор 10:00, 13:00, 18:00 подписывает его «Telegram: бот Claude / бот GPT» и задачу сам не меняет. Живые ответы: бот Claude — при `ANTHROPIC_API_KEY` по выжимке сводки (`ANTHROPIC_MODEL`, по умолчанию `claude-opus-5-5`); бот GPT — при `OPENAI_API_KEY` (`OPENAI_MODEL`, по умолчанию `gpt-5`) **без сводки**: данные клиентов в сторонний ИИ не передаём.
- Файлы и фото боты не принимают: документы клиентов через Telegram не передаём.
- Пишут только chat id из `TELEGRAM_ALLOWED_IDS`; остальным бот называет их id и больше ничего не делает. У каждого бота свой секретный заголовок webhook, выведенный из его токена; `middleware.js` пропускает без пароля только `POST /api/tg`.
- Настройка: в Vercel `TELEGRAM_BOT_TOKEN` и `TELEGRAM_GPT_BOT_TOKEN` (от @BotFather) → Redeploy → открыть `https://svodka-rei.vercel.app/api/tg?setup=1` (за паролем сайта, подключает всех ботов с токеном) → написать боту `/start`, он назовёт id → `TELEGRAM_ALLOWED_IDS` в Vercel → Redeploy.
- Тест без сети: `node tests/tg.test.mjs`.

### Claude → Ольге (ветка outbox)
Ветка Claude создаёт в ветке `outbox` файл `outbox/<время>.json` (GitHub MCP `create_or_update_file`):
`{"text": "ГЕА: отправлять письмо Маркову?", "ref": "gea-ik2710", "buttons": ["Да", "Нет", "Позже"]}`.
`.github/workflows/tg-outbox.yml` отправляет его ботом (секреты репозитория `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`). Нажатая кнопка приходит в `inbox` как «Ответ кнопкой: Да» с `taskId = ref`. Ветка `outbox` не выкладывается (`vercel.json`). Ольге в бот пишет только «Утро и задачи» (§13 регламента).
